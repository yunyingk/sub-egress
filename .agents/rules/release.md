# 版本与发布

- 按实际改动选择语义化版本；核对 `pyproject.toml`、README 版本展示和 `CHANGELOG.md`，确认标签指向预期提交。
- 发布前检查工作区、远端分支和标签、CI、测试、镜像来源、部署目标及回滚方法；不要覆盖其他人的变更。
- GitHub `v*` 标签触发镜像构建；本人的 Gitea/K3s 发布器也会响应 `v*` 或 `k3s-*` 标签。标签可能产生线上副作用，先核对目标和授权。
- 本机没有 Docker 守护进程；需要容器构建或 K3s 主机操作时按用户提供的 WSL 主机约定执行。不要提交个人部署凭据或把私有地址写入公共示例。
- 发布后核对目标镜像、滚动更新、健康检查和受影响的实际功能；如检查失败，报告状态与回滚选择。
